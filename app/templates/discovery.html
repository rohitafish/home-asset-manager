Discovery

Discovery is on-demand only — nothing runs continuously in the background.

"Run nmap scan now" uses an unprivileged TCP-connect scan (-sT). "Run privileged scan (sudo)" uses a full SYN scan (-sS), which is faster and gives more accurate port-state results, via a narrowly-scoped passwordless sudo rule limited to just the nmap binary (see README) — the app process itself still runs as a normal user, not root.

"Discover Sonos household" enumerates every Sonos player from the local port-1400 API of one already-known player, and writes what it finds into the inventory. It seeds only from Sonos IPs already in the inventory (never multicast/SSDP), so run UniFi or nmap discovery first on a fresh database or it will have nothing to seed from. It never renames an existing asset. This collector doesn't fail loudly: if no seed player answers, the run still shows as completed with a summary of status=no_seed_ips or status=no_response — that's the "found nothing" signal, not an error.

"Collect this Mac's hardware identity" reads the serial number, model number and model identifier from system_profiler on whichever machine is running the app, and writes them onto that machine's own asset — it can only ever describe the host it runs on, so run it on the deployed instance (the Mini) to enrich that asset, not from a dev checkout elsewhere.

"Check for vulnerabilities" queries NVD once per detected service and can take several minutes for the whole estate without an NVD_API_KEY in .env (NVD rate-limits unauthenticated requests). The page will just wait for it — that's expected, not a hang.
